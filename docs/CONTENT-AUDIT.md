## How status was decided

A lecture's status comes from its authored sections and its verified code, never from its title, description or
objectives:

| Status | Rule |
|---|---|
| **STRUCTURE ONLY** | The lecture record has a title and a duration and nothing else (no authored section). |
| **PARTIAL** | Some sections exist, but a required section is missing, fails the content validator, or has a broken glossary link. |
| **COMPLETE** | All 24 authored sections present in Bahasa Melayu and English, passing the Professional Programming Education Standard validator, and **every** code example and broken example verified by execution. |
| **NEEDS VERIFICATION** | Complete by the rule above, except that some code is Roblox code that was only **compiled**, never run or tested in Roblox Studio, so its behaviour is unverified. |

Modules, courses, semesters, programmes, academies and faculties are only COMPLETE when **every** lecture in them is
COMPLETE; any mix is PARTIAL, and a unit with no written lecture is STRUCTURE ONLY.

**Subject adaptation.** Every programme that exists today is a programming programme (Python, Lua, Luau). Your
17-point standard maps onto the lecture template as follows; the maths (10) and design (11) points do not apply to
any existing course and are not forced onto them.

| Your requirement | Lecture section(s) that provide it | In written lectures |
|---|---|---|
| 1 Introduction, objectives | introduction, learning_objectives, prerequisite_knowledge | yes |
| 2 Detailed theory | detailed_theory (≥80 words per language), fundamental_concepts | yes |
| 3 Complete learning notes | the 24 sections together; summary | yes |
| 4 Definitions, terminology | technical_terminology + Click-to-Learn glossary | yes |
| 5 Concepts, mechanisms | fundamental_concepts, execution_flow, memory_behaviour, why_this_way | yes |
| 6 Syntax, rules | syntax_rules | yes |
| 7 Step-by-step | execution_flow, line_by_line | yes |
| 8 Practical examples | code_demonstration, complete_examples, practical_demonstration | yes |
| 9 Code + line-by-line | line-by-line explanation covering every meaningful line (validator rule) | yes |
| 10 Calculations (maths) | — | no maths course exists |
| 11 Tools and workflows (design) | — | no design course exists |
| 12 Expected outputs | expected output on every runnable example, verified | yes |
| 13 Mistakes, troubleshooting | common_mistakes, debugging, ≥2 verified broken examples | yes |
| 14 Industry applications | industry_use_cases, software_engineering | yes |
| 15 Exercises and assignments | practical_demonstration tasks + knowledge_check questions in the lecture; **graded exercises, assignments and answers belong to the Practice Center, which is not built** | **lecture part only** |
| 16 Mini projects | mini_project (with verified example solution) | yes |
| 17 Summary, references | summary, references (≥4 links) | yes |

Point 15 is the one systematic gap: no course in the university has graded exercises, assignments or examinations,
because the Practice Center (Phase 5) does not exist yet. The tables below therefore report **lecture materials**;
every course's exercises-and-assessments component is **not started**.

**Problems found:**

1. **Bold text containing a glossary link or inline code is shown raw: a real display defect in the app and in
   exports.** The shared inline parser treats `**…**` as plain text, so `**[[chunk|Chunk]]:**` appears to the student
   literally as **[[chunk|Chunk]]:** in the Lecture Room, the PDF/print view and the Markdown downloads, instead of a
   bold, clickable term. It occurs **32 times (16 per language) in 12 lectures**: LUA101 2.3, 3.1, 3.2, 3.3, 4.3;
   LUA102 2.1, 2.3, 3.2; LUA103 2.1, 4.1; LUAU101 2.2, 4.2. The same cause shows literal backticks in **41** bold
   phrases that contain inline code (for example **`local`**). Because the validator uses the same parser, glossary
   links inside bold text were never checked either. The lecture *source* is correct; the renderer is at fault, so
   the fix is in code, not in content.
2. **14 glossary "related lecture" links point to lectures that are not written** (structure only): `closure` →
   LUA201 1.1, `table` → LUA111 1.1, `metatable` → LUA211 1.1 and LUAU114 1.1, `iterator` → LUA112 2.1, `coroutine` →
   LUA301 1.1, `module` → LUA212 1.1 and LUAU113 1.1, `type-annotation` → LUAU111 1.1, `instance` → LUAU201 1.1,
   `connection` → LUAU203 2.1, `remote-event` → LUAU301 1.1, `datastore` → LUAU302 1.1, `replication` → LUAU214 2.1.
   These come from the original 16-term glossary. A student following them lands on an empty lecture.
3. **Roblox code is compiled only.** 19 units in 7 lectures, plus 11 Roblox glossary examples, have never been run in
   Roblox Studio (status NEEDS VERIFICATION).
4. **Content exists only as metadata** for 887 lectures (title + duration), 295 modules (title) and 73 courses
   (description, objectives, outcomes, references). This is the whole "courses without teaching materials" problem
   you saw; it is not a failed import.

## F. Materials that can be reused without rewriting

- **All 97 written lectures** (Lua Semester 1, Luau Semester 1, LUAU203 1.1): keep as they are. The display defect is
  fixed in the renderer, not in the lectures.
- **80 glossary terms**, each with a verified example.
- **Course metadata for all 82 courses**: description, 4 objectives, 3 outcomes, references, prerequisites, and every
  module and lecture title with its duration. These are the writing outlines for the remaining lectures.
- **Shared concepts between Lua and Luau** (for example closures, metatables, modules, coroutines) can reuse the
  *explanations and structure*, but not the code: the validator forbids duplicate examples, and Luau differs from
  Lua 5.4 in ways the lectures teach explicitly.
- **The authoring and verification pipeline**: the lecture template, validator, content tests, code verifier
  (Lua 5.4 and Luau), the package installer, Install all, exports and the e2e suites.
- **Nothing exists for Python**: no lecture text and no Python verifier yet.
